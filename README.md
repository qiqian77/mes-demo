# 车间设备运维台 · MES 演示

一个面向智能车间设备管理的 MES Demo。**不接 PLC，所有温度、电流读数都由项目内的本地模拟器生成**；核心链路是「采集 → 清洗 → 剩余寿命估计 / 风险分级 → 自动建单 → 工单流转 → 大屏统计」。

这份说明把「哪些是真的、哪些是模拟的」写清楚，方便现场核对。

## 启动

**最省事**：双击 `index.html`。所有依赖都在项目里，离线可用，不需要 npm、不需要构建。

**推荐**（模型文件通过 fetch 加载、地址栏干净）：

```bash
cd mes-demo
python -m http.server 8080
# 打开 http://localhost:8080/
```

Windows 下双击 `start.bat` 会自动起服务并打开浏览器（需要 Python 3）。

> 浏览器需要允许 localStorage。数据存在本机，不会上传。恢复初始演示数据：控制台执行 `Store.reset(); location.reload()`。

## 现场演示步骤（约 1 分钟）

总览页右上角「跑一遍演示」会自动走完四步并停在新建工单详情上。它用固定随机种子 `0xC0FFEE`，保证每次都复现「高风险 → 自动建单」；手动点「重新采样」则每次生成不同的随机读数。

1. **数据与清洗** — 选 `EQ-03 冷却风机`，点「重新采样」生成 120 点带毛刺数据，再点「执行清洗」。虚线是原始读数、实线是清洗后，红点是尖峰、黄点是丢包；下方多出一条清洗记录。「导出 CSV」可拿到原始列与清洗列的完整对照。
2. **风险预测** — 选同一台设备，点「运行预测」。模型输出剩余寿命比例、按额定寿命换算的天数、风险分与等级，以及 7 个特征对风险分的影响。EQ-03 已消耗 88% 寿命，风险分超过 70，页面自动创建一张「待处理」维保工单。
3. **维保工单** — 打开新工单，填处理人 →「派工并推进到处理中」→ 填处理记录 →「标记已完成」。每次流转写入处理时间线。
4. **车间总览** — 待处理工单数、工单统计柱状图跟着变。在线设备数、风险告警、实时曲线也在这一页。

设备台账支持新增、编辑、查看与筛选；工单也可以人工新建。

## 数据与模型从哪来

| 问题 | 回答 |
| --- | --- |
| 数据是现场采集的吗 | **不是。** 由 `js/simulate.js` 按退化机理生成：设备有额定寿命与当前寿命阶段，随阶段增大温升、波动、毛刺、电流纹波单调加重，再叠加工况周期项、高斯噪声、尖峰和丢包。页面实时读数与训练样本调用同一个 `generate()`。 |
| 标签怎么定义 | 参考论文「按寿命比例构造样本」：在设备生命周期的 5%、10%…95% 各取一个 120 点窗口，标签 `remainingRatio = 1 - stage`，即剩余寿命占额定寿命的比例。 |
| 模型怎么来的 | `tools/build-model.mjs` 生成 48 台虚拟设备 × 19 个阶段 = **912 条样本**，按设备 8:2 划分（722 训练 / 190 测试，**测试设备未参与训练与标准化统计量计算**），用 7 个相对量特征做标准化岭回归，闭式解、确定性可复算。 |
| 页面在训练吗 | 不训练。`model/risk-model.json` 是离线训练好的权重，浏览器加载后只做前向计算。 |
| 剩余寿命怎么算 | 模型输出剩余寿命比例 `r ∈ [0,1]`，乘以该设备额定寿命得到天数；风险分 = `100 × (1 - r)`。两者是同一个量的两种表达，不会互相矛盾。42 分需关注、70 分高风险，对应 `r = 0.58 / 0.30`。 |

### 一次预测是怎么算出来的（EQ-03，可逐项核对）

默认演示设备 `EQ-03 冷却风机` 由 `js/store.js` 以固定种子 `20261386` 生成 120 点数据并清洗，`js/model.js` 按 `model/risk-model.json` 的权重做前向计算：

| 特征 | 原始值 | 标准化 z | 权重 | 对 r 的贡献 |
| --- | --- | --- | --- | --- |
| 相对基线温升 | 16.3631 ℃ | 1.208 | −0.30672 | −0.3704 |
| 温度波动 | 1.6795 ℃ | 1.175 | −0.00831 | −0.0098 |
| 温升斜率 | 0.0275 ℃/点 | 1.052 | −0.02299 | −0.0242 |
| 相对基线电流 | 2.7810 A | 1.011 | +0.12358 | +0.1249 |
| 电流波动 | 0.5220 A | 0.570 | +0.01328 | +0.0076 |
| 毛刺占比 | 0.0625 | 1.688 | −0.00964 | −0.0163 |
| 电流纹波 | 0.1874 A | 0.925 | −0.05809 | −0.0537 |

`bias = 0.5`，七项相加得 `r = 0.1581`，截断到 `[0,1]` 后仍是 `0.158`；于是 `RUL = round(0.158 × 128 天) = 20 天`，`风险分 = round(100 × (1 − 0.158)) = 84` → 高风险，页面自动建单。模拟器给这台设备设定的真实寿命阶段是 88%（真实剩余比例 0.12，约 15 天），本次误差 0.038，落在留出测试集 MAE 0.0591 之内。

> **为什么「相对基线电流」的权重是正的**：7 个特征都随退化单调上升、彼此高度相关，岭回归会在共线特征之间分摊权重，因此单个权重的符号不等于物理因果，不能读成「电流越大越健康」。模型要整体看待；页面「特征影响」里逐项加减只用于解释这一次预测的数值来源。

### 一键复现

```bash
cd mes-demo
node tools/build-model.mjs            # 重生成数据集、训练 5 个方法、评估、写模型与对比报告
node tools/build-model.mjs --verify   # 重算并核对权重 / 标准化参数 / 全部指标 / 对比表 / 数据指纹
```

`--verify` 全部一致时输出 `PASS`。脚本只用 Node 标准库，不装任何包。产物：

- `data/samples.csv` — 912 条带标签样本，可直接打开核对
- `model/evaluation.json` — 完整评估报告（含同口径对比摘要）
- `model/comparison.json` — 多模型对比表 + 论文表 5 对照
- `model/risk-model.json` — 权重、标准化参数、训练/评估/对比摘要、数据集 SHA-256
- `model/risk-model.js` — 同上内容的内联副本（由脚本同步生成，供 `file://` 使用）

### 本项目实测指标（留出测试集，190 条）

| 指标 | 数值 | 口径 |
| --- | --- | --- |
| R² | 0.9266 | 剩余寿命比例 |
| MAE | 0.0591 | 剩余寿命比例 |
| RMSE | 0.0742 | 剩余寿命比例 |
| MAE | 7.51 天 | 按各设备额定寿命换算 |
| RMSE | 9.14 天 | 按各设备额定寿命换算 |

常数基线（训练集标签均值）R² = 0，可确认模型学到了退化信号而不是在猜均值。

**这些数字是模拟数据上的留出测试结果，不代表真实设备上的泛化能力。** 页面「模型与实测指标」卡片直接显示这份数据、样本数、划分方式、数据集指纹与复现命令；文献报告值单独放在「参考文献与对照」里，并标注不可比。

## 与论文方法的对比

「风险预测」页底部有两张并排的表，**只有左边那张可以直接比较**。

**左：同口径实测对比。** 在完全相同的 912 条样本、按设备 8:2 划分、7 个特征、同一评估口径下，训练并评估了 5 个方法：

| 方法 | 类型 | MAE（比例） | RMSE（比例） | R² | MAE（天） |
| --- | --- | --- | --- | --- | --- |
| 常数基线 | 对照 | 0.2368 | 0.2739 | 0 | 30.89 |
| 标准化岭回归（页面在用） | 线性 | 0.0591 | 0.0742 | 0.9266 | 7.51 |
| k 近邻回归 k=7 | 非参数 | 0.0635 | 0.0813 | 0.9118 | 8.05 |
| 梯度提升树 60 轮 | 树模型 | 0.0622 | 0.0763 | 0.9224 | 7.93 |
| 多层感知机 7-12-1 | 神经网络 | 0.0614 | 0.0752 | 0.9246 | 7.84 |

这组指标对应论文「表 4 基准模型 + 表 5 评价指标对比」的做法：在同一数据上把线性、树模型、神经网络放在一起比。选岭回归不是因为它最简单，而是它在这份数据上确实误差最低，同时权重可以逐项核对。

**右：论文表 5 对照。** 完整列出 M1 LGBM、M2 LSTM、M3 CNN-BiLSTM、M4 XGBT-DCNN、M5 Informer、M6 XGBT-Informer 六个模型的报告值（MAE / RMSE / R²），来源为《基于特征融合的机械核心部件剩余寿命预测》表 5。

**为什么两组数字不能比大小**：论文用 916 个全生命周期采样文件、直接以剩余寿命天数为标签、14 个原始字段经特征扩展与 XGBoost 筛到 15 维、按 8:2 划分；本项目用 912 条本地模拟窗口、以剩余寿命比例为标签、7 个相对量特征、按设备划分，天数由额定寿命换算而来。数据集、标签、特征与划分口径都不同，MAE 量级自然不同。右表只能看方法谱系与论文自身结论（M6 最优），不能用来判定本项目模型好坏。

> 本项目没有复现 Informer / LSTM / CNN-BiLSTM。左表的 MLP 是神经网络类的轻量替身、GBDT 是树模型类的替身，用来说明「换一类方法会怎样」，不是论文模型的等价实现。`--verify` 会一并核对这张对比表的全部数值。

## 视觉层

`assets/css/glass.css` 是独立的材质层，在 `app.css` 之后加载，只负责毛玻璃与光影，不改布局。

- 背景是三块固定不动的极淡柔光（青 / 琥珀 / 蓝灰），让 `backdrop-filter` 有内容可模糊；没有渐变网格、噪点或发光装饰。
- 玻璃只用于框架与浮层：顶栏、侧栏、KPI 卡、抽屉、遮罩、提示条。表格、图表和表单区域保持接近不透明的白底（`rgba(255,255,255,.95)`），数字与曲线始终清晰。
- 浏览器不支持 `backdrop-filter` 时自动退回实色；系统开启「减少动态效果」时关闭位移与动画。
- 不需要毛玻璃时，删掉 `index.html` 中 `glass.css` 那一行 `<link>` 即可回到原来的纯色样式。

## 技术说明

- **ECharts**：`vendor/` 内置完整包，不依赖 CDN。四张图共用 `js/charts.js` 的坐标轴、提示框与配色，切换页面时统一销毁重建。
- **Uiverse.io**：按钮遮罩滑入、开关滑块、输入框聚焦描边取自 Uiverse.io 的开源 HTML/CSS 组件，按本项目配色做了收敛；`js/universe.js` 按 Universe / crossfilter 的 `filter + query` 语义实现聚合层，台账筛选、告警与工单统计都走它。
- **模型加载**：http 下 `fetch('model/risk-model.json')`；`file://` 下直接跳过 fetch、使用训练脚本同步生成的 `model/risk-model.js`，两份内容一致、不会手工漂移，控制台也不会留下 CORS 报错。
- **数据闭环**：`Store.state` 是唯一数据源，写入即落 localStorage。总览、台账、预测、工单读同一份对象。

## 方法依据与边界

- 刘宗宇、廖雪超.《基于特征融合的机械核心部件剩余寿命预测》. 计算机技术与发展, 2024（网络首发）：按寿命比例构造训练样本、高通滤波 + 小波降噪、XGBoost 特征筛选、15 步输入 / 5 步标签滑动窗口、Informer 回归、S26a / S51d / S100 / Saa3 四类设备。
- 刘晓勇.《基于深度学习的机械设备退化状态建模及剩余寿命预测》. 哈尔滨工业大学硕士学位论文, 2018：SDAE 构建健康指标、LSTM 预测 RUL、退化曲线单调性。

**明确边界**：本项目只借用了论文中「按寿命比例构造样本」和「统计量特征」的思路。模型是标准化岭回归，**没有复现 Informer / LSTM / SDAE**；数据全部来自本地模拟器，**不是论文数据集、也不是现场采集**；未做跨设备型号或跨数据集的泛化验证。文献中的 MAE 4.069 / RMSE 6.422 / R² 0.988 属于 XGBT-Informer 在其数据集上的结果，与本项目实测指标口径不同，不能直接比较；可比的部分是「同口径实测对比」那张表，详见上一节。
